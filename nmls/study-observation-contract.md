# Private study observation windows — bounded internal implementation

September 11, 2026. **Not connected to the learner endpoint or UI. Not attendance, identity, educational-duration validation, approval or credit.** This adds an internal collector for one continuous material window; it does not complete the recovery or delivery system.

## Implemented path

September12 prospective extension: [teaching-phase contract](teaching-phase-contract.md) keeps original offering authority while observing a separate source-bound remediation payload in a newv3-phase journal. Source/child window and continuity owners differ; a child cannot recover an original-phase hold or reset actor time/ROCS. Terminal teaching closes material. This extension is NOT connected to the existing SQL transaction described below; current adapters andv2 guards stay unchanged. Unapplied030 now fences legacy start/commit/replay around explicit phase markers and arbitrates current actor-wide event namespaces; it provides no phase acquisition or joint persistence. See that contract before using the new columns.

`createNmlsObservedPolicyReviewEvaluator` in `lib/nmls-study-observer.mjs` wraps the existing policy/course composer. It derives intervals from stored windows and authenticated receipt intent rather than taking interval boundaries from the browser. Its journal is stored inside the actor-wide policy ledger under `observationJournal`, using the025 transaction for both revisions, runtime, lease and append-only audit, now wrapped by local027's independent exposure guards below. The journal and runtime must be committed together; no observation-side database write occurs before CAS. No live migration was applied.

Each window binds actor, attempt, offering, content digest, session, runtime revision, material fingerprint and opening event. The fingerprint includes the particular unit attempt, quiz attempt/question IDs and delivered feedback. It is canonical across JSONB key reordering. The window has server opening/horizon times and the last qualifying server receipt. Only its opaque ID and expiry are returned to the future learner adapter; journal/audit/source keys are not public projection fields.

First delivery and the first material acknowledgment add zero observed exposure. Collector journal `nmls-study-windows-v2` now budgets the exact issue-to-first-ack gap as **restriction-only** uncertainty before evaluating limits or issuing another horizon. A timely first acknowledgment does not impose a recovery pause. Its trusted unit-time fence prevents a pre-ack heartbeat bridge, including after feedback changes; repeated already-verified answers break that bridge without refreshing inactivity. Consecutive matching visible receipts may contribute their exact server-time interval, at most30 seconds and no later than the previously committed horizon. This is an engagement signal, not proof that a person attended. Window IDs are not authentication or secret credentials; the existing verified actor, lease and both revisions are separately required.

Receipt input accepts only `windowId` and a boolean `visible`. Clocks, elapsed time, identity, grades and replacement state are rejected. The internal policy validator permits this nested field without changing the legacy public validator or endpoint. The legacy runtime's instructional-credit calculation remains separate: observed quiz time, repeated work and time beyond a unit budget must not be treated as newly credited unit time.

A valid receipt can settle the old material before a control or material replacement in the same transaction. Changed feedback, a new unit attempt, a new quiz or a new lease receives a new window with a fresh zero-time acknowledgment. A successful break closes the observation window and cannot erase already recorded rolling exposure. Clean explicit controls may preserve private work as described below; an ordinary policy-denied teaching command still clears active unfinished work after recording its final allowed interval.

## Clean stops, private bookmarks and reserved module quizzes

`lib/nmls-review-continuity.mjs` adds an internal, original actor/attempt/offering/course/digest-scoped bookmark, stored in the runtime through the same025 dual-CAS transaction. Only the durable observer supplies the trusted continuity scope; browser commands cannot supply scope, bookmarks, reservations or save/restore authority. It is not enabled on the legacy public review path.

A timely validated clean logout, explicit break, or active resume may save the current unit's exact provisional milliseconds, verified actions and unit-attempt ID, or bookmark the current quiz. Current/quiz/feedback are removed on the content-free stop. No closing interval becomes additional unit time. A successfully settled closing interval may still increase actor exposure. Clean logout/resume at an exactly exhausted break/daily budget may save work even though further teaching is denied. Idle, missing/stale/hidden/late receipts, rejected settlements and out-of-window controls cannot create a clean bookmark.

Pending bookmarks survive content-free bootstrap, ROCS/break/daily/wall-window refusals and inactivity of that content-free lease. They restore only on a separately allowed `resume`, never through the content-free bootstrap exception. Restoration keeps work but rotates the lease, starts a new observation window, rebinds the unit session, sets receipt/activity timestamps to the current server time and sets `previousEngaged=false`. The first fresh heartbeat and first observation acknowledgment add zero time; absence never bridges into unit or actor study. Logout/resume does not itself count as a break or clear actor usage. `resumeRequired` is the only added public metadata; the bookmark itself is not projected. After restoration, new real inactivity/uncertainty still invalidates that active partial unit.

An ungraded module quiz has a separately pinned private reservation of its ID and question IDs. Clean stops, repeated resume, idle logout, uncertainty and malformed submissions cannot draw new questions; a later permitted quiz start reuses the reservation. Only an actual valid graded submission retires it, allowing the ordinary failed-quiz retry to draw again. Browser-unsent answers are not saved; feedback is not bookmarked. These are provider implementation choices, not quoted NMLS cursor/draft-answer requirements. The final examination uses its separate private attempt history, not this module-quiz reservation.

This is NOT a completed learner bookmarking integration. The real page/HTTP adapter must clear all material and media before sending a stop, preserve exact retries, handle pending-resume metadata and show the restored unit/quiz accessibly. The server receipt is a protocol signal, not proof of DOM removal or identity. Historical observed active quizzes without reservations fail closed, including on logout: do not enable this on old attempts without a reviewed migration/reconciliation path. The old public runtime continues its prior restart behavior when continuity records are absent. Existing025 persists these fields atomically and independently refuses material restoration under denied delivery; it does not independently verify bookmark/reservation contents or their provenance. Trusted server validation is required. Full SQL defense-in-depth and client/end-to-end acceptance remain release holds.

## Independent SQL exposure guards — local027

`database/027_nmls_policy_exposure_guards.sql` is an additive, unapplied forward migration. It preserves025 bytes, renames its commit implementation to an owner-only internal function, revokes direct execution even from `service_role`, and keeps the public RPC signature. The wrapper takes the same grant → actor lease → actor ledger → attempt locks and holds them through validation and the original transaction. Exact existing events delegate to the original scope/digest/replay check before validating any new proposed state. Rollback and both CAS fences remain intact. Helpers are inaccessible to browser and service roles.

For policy02, SQL validates canonical observed/uncertain intervals, typed nonfuture ledger boundaries and old/new journal/window structure. It preserves retained uncertain coverage and the last possible exposure boundary, rejects removal/replacement of an unresolved hold, and refuses an erased or shortened pause. A recovery must match the stored original actor/attempt/offering/content, an eligible reason, prior ROCS acceptance and actual recovery action kinds; an active idle runtime cannot recover simultaneously with logout. Its debit must be the exact union through the evaluated server timestamp, without adding observed time, and it must start a new full provider pause. Zero-length gaps still advance the boundary and start that pause. Missing reason/clock fields cannot pass through SQL NULL semantics.

Break/session resets require the prior pause/rest boundary. `lastStudyAtMs` cannot move backward or be cleared to manufacture rest. Retained observed coverage cannot disappear; combined rolling usage is counted by interval union, not by summing overlapping observed and uncertain time. The break budget uses at least the observed interval coverage since the boundary, even if a proposed counter underreports it, plus uncertain-only coverage. Material-bearing delivery requires a matching current observation window and uses the smaller remaining combined budget. All limits mirror provider policy02, not new claims about regulator-mandated numerical values.

This is defense in depth for trusted server code, not a full SQL reimplementation of the observer or course grader. SQL does not independently recompute material fingerprints, derive every observed interval, prove bookmark/reservation provenance, or reconcile old uninstrumented attempts. Content-free successful controls need no material window. Closed-year preservation remains025's stricter no-new-state rule. No private endpoint/UI, identity provider, actual attendance, real rest, approval or CE credit is created by this migration. Reconcile the next infrastructure handoff and migration numbering before any live application.

Tests run the real observed evaluator and both transaction layers in disposable PGlite, including normal stopping/resume, first acknowledgment, durable recovery, exact/stale retries and rollback after writes. Forged RPCs cannot erase a hold/debt/pause, falsify recovery bounds/kinds or remove a material window. Separate deterministic SQL fixtures cover canonical data, union overlap, counter underreporting, exact budget/pause/rest boundaries, pruning and zero-length recovery. Fixture timestamps/documents are synthetic; the database has one serialized connection, not deployed multi-connection/HTTP/browser acceptance.

## Initial acknowledgment accounting — local029

`database/029_nmls_initial_exposure.sql` is additive and unapplied. It preserves027 bytes and wraps its private guard. A first debit must match the original active unacknowledged window, actor/attempt/offering/content/session/revision, server issue/receipt bounds and unexpired horizon. The audit distinguishes this short initial gap from interrupted-window recovery. It cannot add observed intervals/counters or reset the session/study boundary. Ordinary observed-history retention pruning is allowed, not new observations. Zero-length gaps add no interval but preserve the latest possible exposure boundary. The original uncertainty object is validated before any derived view is used.

For this one transition, a validation-only copy includes the exact newly derived union and boundary; the frozen027 helper then checks the after-state, pause/rest transitions and next horizon against that combined budget. Journal-version normalization also affects only that validation copy. No historical database row, source digest or audit is rewritten. Both helpers are inaccessible even to service_role; the existing locked, dual-CAS/replay RPC remains the sole service entry. Detailed unit-progress provenance still depends on the trusted reducer, not an independent SQL grader.

The policy descriptor adds `initialExposureAccounting`, deliberately changing its binding digest. Old bindings and v1 journals require explicit reconciliation; do not relabel them or reset the actor ledger. An absent journal can initialize only with pristine actor AND runtime revisions, empty exposure/progress and no prior material/bookmark/reservation. Cleared current content and empty counters after legacy uninstrumented teaching are insufficient. Outside-year requests preserve history under the original025 rules, not an in-place upgrade. Existing production review grants and the page remain unchanged.

New regressions cover positive/zero gaps, initial-budget exhaustion, repeated opening/logout, feedback replacement, repeated-answer inactivity, old-journal/historical bootstrap refusal and forged SQL bounds/unions/counters/scopes/horizons. Real025+027+029 transactions cover atomic persistence, post-write rollback, exact replay and recovery. First/remediation/retake tests also load029 to verify coexistence. ## Deliberate stops and remaining work

Missing/stale receipt, hidden page, expired horizon, long gap, changed scope or uninstrumented material/revision creates an **unresolved** window record and stops instruction. The original window is preserved, not tail-clamped, relabelled to another course or discarded on resume/break. Already-instructed attempts cannot silently bootstrap an absent journal. A policy-rejected settlement also preserves the pre-receipt window. Outside the offering's annual window the journal stays unchanged, consistent with025's no-new-policy-state rule; a later offering cannot use its own deadline to settle the old window.

There is **no immediate teaching restart or staff override**. A lost first material response initially blocks this internal path: exact replay returns no fresh window/material, and a subsequent request without the unknown ID preserves unresolved evidence. Bounded same-scope recovery is supported below, replacing the former automatic24-hour aging hold. This remains unsuitable for production until the actual learner adapter, historical accounting and recovery integration are reviewed. Do not delete the journal, set `ready:true` or use the older uninstrumented evaluator as a recovery shortcut.

## Bounded recovery and separate restriction-only debit

The new internal intent `recover_observation` names only `recoveryWindowId` plus the existing event/attempt/revision/current-lease fields. It rejects receipts, supplied times, intervals, grades and replacement state. The server matches the exact unresolved ID and original actor/attempt/offering/content digest. A separately reacquired current lease may differ from the historical lease, which remains unchanged in the evidence.

Policy version `statecourse-oss-session-draft-2026-02` replaces the earlier aging method. Existing01bindings/ledgers are rejected by the ID and policy digest rather than silently upgraded or reset. The versioned actor-wide `uncertainExposure` field is mandatory for02. No live binding or migration was changed.

For a missing/stale/hidden/expired receipt, the next authorized explicit recovery may resolve the original gap. Its `eligibleAtMs` is the first detection, not a promise that instruction may start then. Material/revision inconsistency or rejected policy settlement remains held for review; a changed original scope is also refused. Polling alone never adds a debit or clears evidence.

Before sending recovery, the client MUST clear all old lesson/quiz/feedback surfaces, pause/remove media and invalidate delayed responses. The server budgets the interval from `lastObservedAtMs ?? issuedAtMs` through the recovery request's server timestamp. It does NOT truncate at the old30-second horizon: that horizon cannot establish when cached material disappeared. The boundary is a conservative protocol/accounting assumption, NOT proof of attendance, human rest or inability to view an offline copy.

`lib/nmls-uncertain-exposure.mjs` stores these intervals separately from `studyIntervals`, `studySinceBreakMs`, `lastStudyAtMs` and unit progress. Observed and uncertain intervals are unioned for restriction calculations so overlap counts once. Last possible exposure, including the debit boundary, controls new-session rest; pruning rolling intervals does not remove that boundary. No debit becomes observed study or educational credit. New v2 windows now account separately for successfully acknowledged initial gaps as described above; legacy/uninstrumented study still requires explicit reconciliation before a complete delivery-enforcement claim.

Every successful recovery starts a **fresh10-minute content-free pause**, using the draft provider break choice. A break started or completed while exposure was unresolved cannot satisfy this new pause. An explicit `end_break` may finish it after the full interval; if course inactivity has expired, persist logout and reacquire a content-free lease first. The pause does not erase rolling usage or the wall-session/rest limit. Short gaps therefore need not impose an arbitrary24-hour hold, while accumulated or long uncertainty can still block under ordinary limits. No universal NMLS10-minute network recovery rule is claimed.

The original grant must still be authorized, the original annual window open, ROCS verified/accepted and the current lease valid. An idle request first logs out and cannot recover simultaneously. Missing/changed authority or scope leaves the hold in place. Completed lessons remain saved progress, not live current/quiz/feedback that could permanently prevent recovery.

Successful resolution clears the current unresolved hold, adds the separate debit and starts that pause. The complete original object, reason, window fingerprint, detection event, debit bounds, recovery event and earliest pause end are recorded in the same atomic append-only audit transaction. Observed history, completed progress and ROCS acceptance remain unchanged. The underlying `check_recovery` step validates context without pruning observed history or opening a session; the bare composer cannot claim recovery. A later completed break resets the since-break counter through the existing explicit policy action, not through the recovery request. New material requires normal limits and a new zero-time first acknowledgment.

Closed-year, expired/revoked-grant or changed-binding cases remain held; resolution from another/new-year offering is not supported by025. No historical observed interval is invented or reassigned. The existing025 transaction stores this additional JSON atomically; local027 now independently checks the uncertain-debit union and prior hold/pause transitions as described above. The updated evaluator remains mandatory; complete observer/continuity provenance, binding/version reconciliation and real concurrent checks remain integration work. None of023/024/025/026/027 was applied live.

## Local client lifecycle helper, not a connected page

`lib/nmls-delivery-lifecycle.mjs` implements generation-fenced delivery and clear-before-control/recovery with injected synchronous render/media-cleanup callbacks, monotonic clock and timers. A lease uses the request-send monotonic time plus a trusted server-relative budget; network/render/cleanup delay never extends it. Old expiry invalidates pending renewal tokens, including when a timer was delayed. Hidden/disconnected/disposed/faulted states and duplicate, replayed, denied or control responses cannot restore material. Callback failure prevents further delivery and recovery transmission, but cannot prove a defective external cleanup actually removed a DOM node.

This helper is not imported by the existing page. The future authenticated adapter must supply the server-derived relative budget, map real commands, serialize exact retries with the existing client, clear all surfaces/media and wire page visibility/network/OS-resume behavior. Suspended JavaScript cannot run a timer; rechecking on the next helper call is not proof of instantaneous browser-side removal during sleep. Actual multi-tab/browser/assistive-technology testing is still required.

Still required: historical-window settlement under its original context, provider/human acceptance of this draft resolution policy, atomic cross-offering transfer, HTTP receipt/budget transport and actual expiry enforcement, accessible learner break/rest/network recovery, real ROCS, BioSig integration, deployed concurrent/browser tests and human validation. The current browser does not send these receipts, so **do not connect this wrapper directly to that browser or provision policy-bound production grants**.
