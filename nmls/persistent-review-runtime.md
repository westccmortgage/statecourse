## Concrete path

1. An authorized server/staff operation grants a named existing student private review access to a course key and immutable SHA-256 digest, with expiry and recorded basis. No public self-grant or paid entitlement is created here.
2. `POST /api/student/nmls/review` checks the configured same origin, JSON type/size and existing verified Supabase session. It reuses `requireStudentSession`; that existing helper synchronizes the `students` row. No user-editable profile role or browser student ID authorizes the review.
3. `start` returns an existing/new attempt for the exact grant. It hides any active session ID. An explicit `resume` rotates the study lease and discards only unfinished unit/quiz work; completed units survive.
4. `open_unit` enforces ordered units and earlier module quizzes. Readable lesson content and the current formative question are projected from the private manuscript; keys are not returned with questions.
5. A server timestamp comes from the database. The reducer caps credible visible intervals at the required amount and excludes long gaps/background intervals. `interaction` represents a validated-format, client-observed gesture; `heartbeat` is automatic polling and does not refresh inactivity. Explicit accepted study actions, including a wrong submitted answer, may refresh activity without granting instructional time or passing the unit action gate. Repeating an already verified correct answer grants neither. This distinction is not proof of human identity, and scripted activity cannot be ruled out by browser observations alone.
6. Unit action answers and module quizzes are graded server-side. Each5-question module review samples its own12–16-question private formative bank and passes at80%. It is not an independent approved final exam. Failed review can be retried; formal remediation and final-exam policy remain to implement. Written/reflection assignments remain readable but are not yet collected or graded; passing one unit action does not prove completion of every embedded exercise.
7. Commit reacquires the active grant and actor-wide study lease, then locks the attempt. It rechecks grant expiry after waiting, requires exact revision/session/content, and refuses stale evaluation clocks (including a six-minute boundary crossed during processing). The service reloads once on clock-refresh conflict. A competing successful write still requires client resynchronization.
8. Exact repeated event ID + canonical payload returns the original outcome with no extra write or time. Different payload with the same ID is rejected. Events store compact lesson references; response content is rehydrated from the same pinned course digest.
9. Six minutes of inactivity logs out of this review course, discards the current unit's provisional time/actions or an unfinished quiz, and preserves completed prior units. The logged-out state and invalidation audit COMMIT even when HTTP returns401. No SQL exception is raised after writing the logout. Active quiz gestures prevent inactivity; there is no invented six-minute quiz deadline.

## Database boundaries

Migration `database/023_nmls_review_runtime.sql` creates four isolated tables and three service-only functions. Additive024 adds the fourth service-only function, `nmls_review_list`, for the authenticated student's own active, unexpired grants. All tables have RLS enabled. `anon`, `authenticated` and `PUBLIC` have no table privileges or function execution. Actor/revision comparisons are NULL-safe. The service-role key stays server-side. Public list responses omit grant evidence, operator identity, private questions and leases; stale content hashes are marked unavailable rather than silently upgraded.

These files were previously named020/021 and remain byte-identical; neither was applied to production. They were renumbered because GitHub main at7a5cae8 already has admin/training020–022. Additive025 introduces the opt-in policy transaction described in [the session contract](session-policy-contract.md). It hides policy-bound grants from legacy discovery and refuses their old start/context/commit path, leaving ordinary unbound grants unchanged. The new transaction is not yet a public learner flow. Integrate in an explicit reviewed order after reconciling main; do not run a directory glob, which would include a rollback script.

The actor-wide lease fences other NMLS review attempts even across different grants. A second explicit takeover invalidates the old session's authority to write. A new tab cannot get the old lease by ordinary `start`. The new `/student/nmls-review/` study UI implements explicit resume and conflict recovery; the lease lives in page memory, never persistent browser storage. Reloading does not silently take over another device.

Invalid calendar dates are rejected rather than normalized. Fresh expiry checks precede insert and success receipts. Identical grant IDs can be retried, but a revoked or changed grant is never overwritten. Nothing has been provisioned in production with this CLI.

No foreign key, trigger or RPC in023 creates or changes payment, checkout, enrollment, course approval, certificate or banking records. National NMLS courses are not mislabelled as California or cloned into fifty state course rows. This private namespace is not yet the approved-credit data model.
