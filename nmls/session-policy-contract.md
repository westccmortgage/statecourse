## Source requirements and provider choices

Main and an independent read-only agent checked the official v17 HTML specification, effective January1,2026. Search also returns an older v15 PDF; that legacy PDF was not used as the current standard.

- [§5.5 ROCS](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/nmls/pubs/nmlsEdFuncSpec/education/funcSpec/maps/topics/nmlsFS_OSS_ROCS.html): V4 must be displayed and acknowledged through an LMS click-through at the start of each course; keep the agreement log five years. Include the document on the course-material cover or a standalone second page. An account-wide acceptance or a summary alone is insufficient.
- [§1.5.4 breaks](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/nmls/pubs/nmlsEdFuncSpec/education/funcSpec/maps/topics/nmlsFS_timeReqsMandatoryBreaks.html): interrupt instruction before it runs beyond four hours; break time is not instructional time. This section does not specify a minimum break length.
- [§1.5.5 session](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/nmls/pubs/nmlsEdFuncSpec/education/funcSpec/maps/topics/nmlsFS_timeReqsMaxCourseSession.html): limits a course session to12 hours within one24-hour day. It does not explicitly define a credited-minute cap, rolling/calendar reset, timezone or cross-provider aggregation.
- [§1.5.6 seat time](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/nmls/pubs/nmlsEdFuncSpec/education/funcSpec/maps/topics/nmlsFS_timeReqsEnsureSeatTime.html): an instructional hour is50 clock minutes of engagement; gaming/idle accrual must be prevented. The break/session sections do not expressly resolve200 vs240 active minutes or600 vs720 minutes.
- [§1.5.2 scheduling](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/nmls/pubs/nmlsEdFuncSpec/education/funcSpec/maps/topics/nmlsFS_timeReqsCourseSched.html) and [§5.3.5 OSS scheduling](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/nmls/pubs/nmlsEdFuncSpec/education/funcSpec/maps/topics/nmlsFS_OSS_timeReq.html): annual CE must finish in its required calendar year. The seven-day reporting period does not extend learner completion. Earlier agency deadlines still matter; these sources do not impose one universal year-end timezone.

`config/nmls/session-policy.mjs` deliberately labels these **draft StateCourse implementation choices**, pending provider/reviewer acceptance: mandatory10-minute break after200 restriction-budget minutes;600 restriction-budget minutes in every rolling24h;12-hour wall session; a new wall session only after12 hours since the latest observed or uncertain-exposure boundary. Version02 adds separate restriction-only uncertainty intervals, unioned with observed intervals without double counting. They are not observed participation or credited minutes. Same-scope recovery starts a fresh10-minute pause. These are conservative platform choices, not an assertion that NMLS specifies each numerical conversion, network recovery rule or algorithm. Breaks do not reset rolling usage. A page reload or another offering does not reset the actor's ledger. Existing01states/bindings are rejected, not silently migrated into empty02usage.

The annual window has no implicit timezone, January1 conversion or seven-day grace. The trusted offering must supply opening/cutoff instants, IANA timezone, delivery year and a documented deadline-basis ID. Window validation checks calendar consistency, not the substantive authenticity of that basis. The adapter must verify the actual course approval, current agency deadlines and student eligibility separately. Late CE is rejected by this annual-only component; unfinished2026 work is not relabelled2027.

## Implemented behavior

`lib/nmls-session-policy.mjs` is a pure server domain component. It accepts a trusted actor-wide ledger, a restricted command, trusted offering and server evidence. Clock rollback, actor mismatch, stale revision and browser-style extra clock/grade/policy fields are refused. All results retain `creditIssuanceAllowed:false`.

Acceptance binds actor, offering, content digest, ROCS version/document digest, a server presentation receipt and server acceptance time. An unverified document is refused. Tests use explicitly synthetic hashes/presentation evidence; the actual complete V4 document still needs approved sourcing, byte pinning, accessible in-LMS display and export placement. This component cannot prove that a learner actually read a document. See [ROCS source review](rocs-source-review.md) for the four-page document inventory, FAQ implementation details and the unresolved original-byte acquisition. ROCS reading/acknowledgment is not instructional time; the five-year retention period starts with the course, not completion.

Study observations include assessments, repetition and subsequently invalidated work; they are not awarded credit. Observations use bounded30-second server intervals. Receipt ordering is separate from study coverage: an intervening navigation check or another offering's acceptance must not erase an actual study interval. Completed break/new-session boundaries still exclude pre-boundary intervals. Overlapping/replayed intervals do not accumulate again.

An access check returns the exact maximum next study interval before break, rolling usage, wall-session or annual cutoff. The adapter must stop new delivery at that horizon. If an observed interval nevertheless crosses a study limit, the component records the actual exposure and a refusal; a later access check cannot reopen simply because the violating interval was discarded. This is an accounting/violation record, not retroactive permission or CE credit.

Break start/end are explicit; repeat start does not restart the timer, early end is refused, and no study is allowed during the break. Recovery is a distinct event that starts a fresh pause after its conservative gap debit; a pre-recovery break cannot satisfy it. Polling denied access does not extend the rest deadline. New-session rest uses the latest observed or uncertain boundary, not arbitrary last request time. A completed break resets only the since-break counter. A new session does not clear rolling24h usage. The annual cutoff is exclusive and blocks new operations without backdating or transferring year credit.

The observation crossing check conservatively reserves a whole next interval against usage at its start; it can refuse an interval while old usage is aging out within that interval. The delivery horizon is shortened to the remaining start-time budget, so a valid issued window cannot exploit that boundary. This is conservative reservation, not exact continuous-window optimization or a claim that NMLS mandates this algorithm.

## Implemented private transaction slice

`database/025_nmls_review_session_policy.sql` adds immutable per-grant offering/policy bindings, one actor ledger per student (not per grant or policy version), durable ROCS presentation receipts and append-only actor events. No bindings or documents are seeded. Bind only before an attempt exists; an exact repeated bind is idempotent, changed configuration is refused. Changing a policy does not initialize a fresh usage ledger. These are trusted service-only operations, not browser grants or evidence of document authenticity.

The internal transport `netlify/functions/_lib/nmls-policy-transaction.mjs` validates input, loads the grant-pinned offering and both revisions using database time, checks the canonical policy digest, obtains any presentation from the database rather than a browser object, and invokes a **required trusted server evaluator**. It is deliberately not imported by the current public review endpoint. The original persistence suite retains its explicitly test-only evaluator. A real composed domain evaluator now exists as described below; neither it nor that fixture is a production engagement collector. Do not wire either into HTTP or advertise enforcement without the collector, actual full-document renderer and learner recovery.

Atomic commit takes locks in grant → actor lease → actor ledger → target attempt order. It verifies exact actor-event replay before both revision comparisons, fences other leases, commits attempt/ledger/both audits together, and preserves exposure when policy denies. A synthetic forced failure after attempt write proves rollback of all parts. Per-offering and cross-offering retries cannot double-count. A response replay is historical: the transport redacts its lesson/quiz/feedback material rather than granting fresh access. A delayed nonduplicate response is also redacted using a conservative database-time plus server-monotonic-elapsed bound.

SQL rechecks annual-window boundaries both before and after writes, including successful ROCS/break operations that deliver no lesson. Closed-window state may only preserve usage and perform permitted cleanup, never activate/rotate a session or refresh activity. SQL also rechecks grant expiry, six-minute idle boundary, maximum delivery horizon, wall-session deadline and remaining break/rolling budgets. General domain calculation remains trusted server code; these SQL guards do not prove a human attended. Idle-unit invalidation and refusal are persisted normally, not rolled back by throwing a policy-denied HTTP error.

The old start/context/commit functions are retained as owner-only internal implementations and their original names become guarded wrappers. Permission tests actually switch to service_role and browser roles; service_role cannot invoke the renamed internal functions or directly read/write new tables. Legacy discovery hides policy-bound grants until the new flow exists. Legacy unbound review remains usable, including lease exclusivity, but its study **does not feed the new policy counters**. Hence this slice demonstrates aggregation across policy-bound offerings only, not all historic/uninstrumented work or other providers.

Deployment numbering: NMLS020/021 were never applied to production and are now named023/024 with identical bytes; GitHub main at7a5cae8 already uses020/021/022 for admin/training. This025 migration follows the two renamed NMLS files. Local027 adds an independent commit wrapper for policy02 interval unions, prior debt/hold/pause preservation, recovery scope and safe resets;026 is the separate first-final ledger. See [SQL exposure guards and explicit limits](study-observation-contract.md#independent-sql-exposure-guards--local027). Reconcile the NEW infrastructure handoff and apply an explicit forward list; do not execute rollback files. None of these migrations was applied to a live database.

## Composed control/review evaluator — local checkpoint

`lib/nmls-policy-review.mjs` combines policy commands with the existing course runtime. Internal policy steps now have one finalizer: a validated observation followed by a break/check/other action advances the actor revision and receipt exactly once. Its audit keeps the observation separate from the control result. No caller resets a revision after committing two transitions.

The first resume can create a **content-free** lease so the learner can reach per-offering ROCS acceptance; missing agreement cannot deadlock that bootstrap. Resume during a break permits controls, not instruction. An idle acceptance, break completion or resume first persists course logout without applying that requested policy action. A separate explicit resume is required. Completed-review break controls report their actual successful result without changing the completed units or issuing credit.

Trusted runtime control/check options replace the fixture's unknown-command placeholder. Policy denial and protocol/sequence refusal return no lessons, quiz or rationale and invalidate the unfinished unit/quiz; completed units and observed actor exposure remain. This conservative draft interruption behavior needs learner/reviewer validation. Ordinary teaching feedback is distinct: an incorrect formative answer, failed module review or unmet unit requirement may retain instruction/explanation **only while policy permits delivery**. Delivery horizons additionally end at the six-minute human-inactivity deadline, even if policy time remains. Automatic checks never refresh human activity.

**A complete production observation collector is still missing.** The base composer without a trusted `observe` implementation supports content-free controls only and refuses study with `study_observation_not_connected`. Its tests explicitly inject synthetic intervals. The [bounded observation-window collector](study-observation-contract.md) derives continuous intervals and preserves interruptions using025. Version02 can resolve a same-scope gap with a separate conservative debit and fresh pause, without the former arbitrary24-hour wait for every interruption. Original evidence remains in atomic audit and no study/credit is awarded. Collector v2 and local029 now account for first-ack gaps as restrictions only, without a forced recovery pause. The new policy descriptor changes its binding digest; old journals/bindings are not silently upgraded. A local generation-fenced client helper implements clear-before-recovery and monotonic delivery expiry, but it is not connected to the page or HTTP transport. Legacy exposure, learner bookmarking integration, rejected settlements, expired grants and year transitions remain incomplete. Local027/029 complement025 with independent uncertain-debit arithmetic and preservation guards; the trusted evaluator, complete observer/continuity provenance and further integration review remain mandatory. Neither fixtures nor these components prove participant activity. Simply returning `ready:true`, discarding gaps or deriving exposure from credited minutes is not valid integration.

The new suite runs the real composed evaluator through the existing transaction transport and025 in a disposable database for bootstrap, durable presentation acceptance, replay, blocked study, breaks and idle cleanup. A separate deterministic fixture covers cap-excess/quiz exposure, wrong-answer explanations, single revision, protocol-denial redaction/continuity, exact break/idle/cutoff boundaries and terminal controls. Existing unbound runtime paths and content hashes remain unchanged. No HTTP import, UI control, database schema, live setting or payment integration was added in this checkpoint.

1. Implement the trusted observation collector, then connect the composed evaluator/025 to the real HTTP path. Never accept observation intervals, evidence/state/clock or grading from browser JSON. The implemented transaction and composed controls are not a completed course delivery adapter.
2. Serialize all simultaneous offerings/tabs/devices for the actor. Counters must survive new enrollment/grant/attempt, voluntary exit, inactivity rollback and failed assessment. No claim is made about study on other providers' systems; integration/policy for unavailable external history remains unresolved.
3. Integrate bounded delivery horizons with actual engagement/quiz observations. Stop instructional accrual/content delivery at the earliest limit, preserving normal idle-unit invalidation rules. Check trusted database time again at commit, including cutoff crossing while a request waits for a lock. A per-request policy calculation alone cannot close that race.
4. Display the complete pinned ROCS in the LMS, capture explicit unchecked-by-default agreement per offering, retain its immutable presentation/acceptance evidence and archive the document for five years; place it in course exports. 5. Add learner-facing break/rest/deadline recovery, exact retry and resume behavior; independently test deployed SQL/HTTP/UI with concurrent requests and real clocks. No additional study time or approval is implied by a green domain test.
